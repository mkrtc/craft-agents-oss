# v0.11.13 — Project Memory Connections

## Features

- **Qdrant-backed Project Memory connections** — Added a global Memory connection registry for local and external Qdrant instances, with managed memory-space refs, per-session read selection, explicit write targets, and server-side authorization so agents only use memory spaces selected for the current session/project. (`208f7c92`, `9f81f6cf`, `dfc8cc2b`)
- **Project Memory connection management UI** — Project Memory now includes UI for creating, editing, deleting, and checking Qdrant connections and spaces. API keys are write-only, stored via the credential manager, and never returned to the renderer. (`1afaa3ac`, `e237d965`, `0369ac28`)
- **Session Memory selector** — Chat sessions can explicitly choose which memory spaces are readable and which writable non-global space receives new memories, with live session metadata updates. (`ea45a2aa`, `21c5760f`)

## Improvements

- **Project Memory prompt awareness** — The agent system prompt now explains that Project Memory may be backed by local or external Qdrant and instructs agents to respect current session/project memory selection while never storing secrets. (`f87997a1`)
- **Safer Memory persistence and concurrency** — Session headers and Memory connection repositories now use stricter canonicalization, bounded persistence, durable baselines, transactional repairs, and race-tested read/write paths. (`696a0848`, `3c93724a`, `d3d35495`, `51451088`, `1577b11b`)
- **Explicit-only agent attribution** — Craft Agent, Claude, and other agents are no longer added as commit co-authors or contributors by default. Agent attribution is opt-in only when the user explicitly requests it. (`cd147f15`)

## Bug Fixes

- **Project Memory scope authorization** — Agent memory tools now reject cross-project IDs, derive location fields from the current server-side session context, and safely exclude unavailable project scopes instead of allowing model arguments to broaden access. (`420385a1`, `3f284e45`)
- **Memory credential hardening** — Memory API keys are resolved only after authorization, stored through the credential manager, and kept out of RPC responses and logs. (`aaeef989`, `2c961d14`, `122f176d`)
- **Connection UI robustness** — Fixed a blocking delete confirmation that could freeze the Electron UI and hid synthetic default/environment connections from user-facing management lists. (`385a715b`)
- **Config test isolation** — Memory and config tests now isolate config roots across Bun module caches to avoid cross-test leakage. (`9c6fc273`)
